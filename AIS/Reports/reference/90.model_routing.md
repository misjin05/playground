# LLM 모델 라우팅(Model Routing)의 개념과 도입 이유

## 1. 질문 (Question)
> **Q.** 일반적으로 모델 라우팅을 하는 게 특정 모델에 부하 또는 토큰 사용량을 줄이려는 건가요? 모델 라우팅을 적용하는 핵심 이유가 무엇인가요?

---

## 2. 핵심 답변 요약 (Executive Summary)
AI 시스템에서 **모델 라우팅(Model Routing / Cascading)**을 적용하는 본질적인 이유는 **"모든 작업에 초대형 플래그십 모델을 쓰지 않고, 작업 난이도와 특성에 맞는 최적의 모델(경량/특화/고성능)을 배분하여 비용·속도·인프라 안정성·정확도를 동시에 극대화"**하기 위함입니다.

---

## 3. 모델 라우팅을 적용하는 4대 핵심 이유

### ① 비용 및 컴퓨팅 자원 최적화 (Cost & Resource Optimization)
- **문제점**: 대형 모델(70B+ 또는 상용 고성능 모델)은 1회 호출당 소모되는 GPU 연산량, 메모리(VRAM), 전력, 토큰 단가가 매우 높습니다.
- **해결 방안**:
  - "JSON 포맷 변환", "단순 키워드 추출", "정형 로그 파싱", "도구 파라미터 유효성 검사" 같은 단순 작업은 **경량 모델(3B~8B급)**로도 대형 모델과 동일한 품질을 달성합니다.
  - 고난도 추론(아키텍처 설계, 복합 디버깅 등)에만 대형 모델을 투입하고 단순 작업은 경량 모델로 처리하여 **전체 추론 비용과 자원 소모를 50~80% 이상 절감**합니다.

---

### ② 응답 속도 및 지연 시간 단축 (Latency & Throughput Improvement)
- **문제점**: 모델 파라미터가 클수록 Time to First Token (TTFT)과 토큰당 생성 시간(TPOT)이 길어집니다.
- **해결 방안**:
  - 에이전트 루프가 10~20단계(Step) 진행될 때, 매 단계마다 대형 모델을 호출하면 사용자 체감 대기 시간이 수십 초 이상으로 늘어납니다.
  - 중간 검증이나 단순 도구 호출 파라미터 생성 등은 응답이 빠른 경량 모델로 처리하여 **전체 에이전트 작업 완료 시간(End-to-End Latency)을 대폭 단축**합니다.

---

### ③ 인프라 부하 분산 및 쏠림 방지 (Load Balancing & Capacity Management)
- **문제점**: 사내 GPU 서버 자원은 한정되어 있는데, 모든 개발자가 가장 성능 좋은 '특정 1종 모델'로만 요청을 집중시키면 해당 서버에 **큐 대기(Queueing delay), 지연 급증, GPU OOM(Out of Memory), 요청 거절(Throttling)**이 발생합니다.
- **해결 방안**:
  - 사내에 기구축된 여러 서빙 모델(경량 분석 모델, 코드 특화 모델, 고성능 범용 모델 등)로 트래픽을 분산시켜 **사내 AI 인프라 전체의 가동률과 처리량(QPS)을 극대화**하고 특정 모델의 병목을 예방합니다.

---

### ④ 도메인 / 태스크 특화 성능 극대화 (Specialized Task Performance)
- **문제점**: 크기가 큰 범용 모델이라고 해서 모든 작업(코드 생성, 로그 파싱, 자연어 번역 등)에서 항상 가장 뛰어난 결과를 내는 것은 아닙니다.
- **해결 방안**:
  - 특정 도메인(예: 코드 데이터셋으로 집중 파인튜닝된 Code-LLM, 긴 컨텍스트에 특화된 모델)에 맞는 모델로 전달할 때 **오히려 더 적은 토큰과 시간으로 더 높은 정확도(Pass Rate, F1-Score)**를 얻을 수 있습니다.

---

## 4. 에이전트 하네스 관점에서의 시사점
1. **정적 라우팅 (Static / Manual Selection)**: 사용자가 작업 유형(예: 테스트 작성, 코드리뷰, 로그 분석)에 따라 적합한 사내 서빙 모델을 직접 지정.
2. **동적 라우팅 (Dynamic / Rule-based Cascade)**: 
   - 1단계: 경량 모델로 빠른 초안/파싱 수행.
   - 2단계: 실패하거나 복잡도가 높은 경우에만 고성능 모델로 에스컬레이션(Fallback).
3. **효과**: 개발자 생산성 유지 + 사내 GPU 인프라 부하 최적화 + 토큰 비용 억제.

💡 요약
**"닭 잡는 데 소 잡는 칼(초대형 모델)을 쓰지 않고, 칼의 용도(경량/특화/범용)에 맞게 작업을 배분하여 속도·비용·인프라 안정성을 모두 챙기려는 것"**이 모델 라우팅의 본질적인 이유입니다.
