# AI 시스템 8대 품질 속성(Quality Attributes) 및 평가 지표(Metrics) 종합 가이드

> **참조 강의자료**: `AIS / reference / 1-2 AI Engineering`  
> **기반 표준**: ISO/IEC 25059 (AI System Quality Model), ISO/IEC 25010/25012, ISO/IEC 29100, NIST AI RMF, EU AI Act

---

## 1. 개요: AI 시스템 품질 및 Trustworthy AI

### 1.1 AI 품질 모델의 등장 배경
전통적인 소프트웨어(ISO/IEC 25010)와 달리, AI 시스템은 **1) 확률론적 동작 특성**, **2) 일반화의 한계**, **3) 비결정론적 특성(생성형 AI)**을 내재하고 있습니다. 따라서 단순한 "기능 정확성"만으로는 신뢰성을 보장할 수 없으며, 이를 보완하는 다각적인 품질 속성(Quality Attributes, QA)이 필수적입니다.

### 1.2 AI 시스템 8대 품질 속성 요약
| 품질 속성 (QA) | 영문 명칭 | 핵심 정의 및 역할 | 주요 집중 상황 |
| :--- | :--- | :--- | :--- |
| **1. 기능 정확성** | Functional Correctness | 의도하는 정답을 요구되는 정밀도로 오류 없이 제공하는 능력 | 정상적(Normal) 안정적 추론 영역 |
| **2. 강건성** | Robustness | 악조건(미학습 데이터, 노이즈, 공격, 간섭 등) 속에서도 기능 정확성을 유지하는 능력 | 비정상적(Abnormal)·가혹한 위협 상황 |
| **3. 프라이버시** | Privacy | 개인 식별 정보(PII) 및 사생활이 부당하게 수집·유출·추론되지 않도록 보호하는 능력 | 데이터 처리 및 적대적 추론 공격 상황 |
| **4. 공정성** | Fairness | 보호 속성(성별, 연령 등)에 따른 부당한 차별 없이 결과를 균등·일관되게 도출하는 능력 | 다수-소수 집단 간 결과 및 오차 비교 상황 |
| **5. 수행 효율성** | Performance Efficiency | 명시된 시간, 처리량, 자원(GPU, 메모리, 전력) 제약 내에서 기능을 완수하는 능력 | 고부하, 실시간성 요구, 자원 제약 환경 |
| **6. 기능 적응성** | Functional Adaptability | 운영 도메인(환경, 객체, 규제 정책 등)의 변화에 대응하여 스스로를 적응시키는 능력 | 운영 도메인 확장(Expansion) 및 변경(Change) |
| **7. 제어 가능성** | Controllability | 인간 또는 외부 제어기가 AI 동작에 개입하여 신뢰성 회복 및 안전 상태로 전환하는 능력 | 자율 시스템의 한계·고립·위험 발생 상황 |
| **8. 설명 용이성** | Explainability | AI 판단 결과에 대한 '이유(메커니즘)'와 '타당성(근거)'을 인간이 납득하도록 표현하는 능력 | 사후 분석, 감사, 사용자 납득 및 신뢰 구축 |

## 2. 품질 속성별 상세 정의 및 평가 지표 (Metrics)

---

### [QA 1] 기능 정확성 (Functional Correctness)

#### 1. 개념 및 정의
- **정의**: 사용자가 의도하는 **정확한 결과(Correct Results)**를 **필요한 정밀도(Needed Degree of Precision)**로 제공하는 능력.
- **불완전성 원인**: 통계적 분포 학습에 따른 확률론적 오차(배경 편향, 환각), 미학습 영역(Unseen)에 대한 일반화의 한계, 확률적 샘플링(Temperature, Top-p)에 따른 비결정성.

#### 2. Task 유형별 평가 지표 (Metrics)
| Task 유형 | 지표 명칭 | 산출식 / 계산 원리 | 적용 상황 및 해석 |
| :--- | :--- | :--- | :--- |
| **분류 (Classification)** | **Accuracy** (정확도) | $\frac{TP + TN}{TP + TN + FP + FN}$ | 클래스 분포가 균일할 때 전체 맞힌 비율 |
| | **Precision** (정밀도) | $\frac{TP}{TP + FP}$ | 모델이 Positive라 예측한 것 중 실제 Positive 비율 (오탐 최소화) |
| | **Recall** (재현율, TPR) | $\frac{TP}{TP + FN}$ | 실제 Positive 중 모델이 맞힌 비율 (미탐 최소화) |
| | **F1-Score** | $2 \times \frac{\text{Precision} \times \text{Recall}}{\text{Precision} + \text{Recall}}$ | 정밀도와 재현율의 조화평균 (불균형 데이터) |
| | **PR-AUC / ROC-AUC** | ROC 곡선 또는 PR 곡선 아래 면적 | 임계값(Threshold) 변동 시 모델의 전반적 변별력 평가 |
| **회귀 (Regression)** | **MAE** (평균 절대 오차) | $\frac{1}{n} \sum \|y_i - \hat{y}_i\|$ | 오차의 절대적 크기 평균 (이상치에 덜 민감) |
| | **MSE / RMSE** | $\text{RMSE} = \sqrt{\frac{1}{n}\sum (y_i - \hat{y}_i)^2}$ | 큰 오차에 더 큰 페널티를 부과하는 평균 오차 |
| | **MAPE** (평균 절대 백분율 오차) | $\frac{100\%}{n} \sum \|\frac{y_i - \hat{y}_i}{y_i}\|$ | 스케일 독립적인 백분율 오차 |
| | **$R^2$** (결정계수) | $1 - \frac{\sum (y_i - \hat{y}_i)^2}{\sum (y_i - \bar{y})^2}$ | 모델이 데이터의 분산을 설명하는 비율 ($0 \sim 1$) |
| **군집화 (Clustering)** | **Silhouette Score** | $s(i) = \frac{b(i) - a(i)}{\max(a(i), b(i))}$ | 군집 내 응집도와 군집 간 분리도 평가 ($-1 \sim 1$) |
| | **Davies-Bouldin Index** | 군집 간 거리 대비 군집 내 분산 비율 | 낮을수록 군집화가 잘 이루어짐 |
| **추천 (Recommendation)** | **Precision@K / Recall@K** | 상위 K개 추천 결과 중 정답 아이템의 비율 | 제한된 추천 슬롯 내 적중률 |
| | **NDCG@K** | $\text{NDCG}@K = \frac{\text{DCG}@K}{\text{IDCG}@K}$ | 상위 순위에 더 큰 가중치를 부여하는 랭킹 적중 지표 |
| | **MRR / MAP** | 첫 번째 정답 순위의 역수 평균 / 평균 정밀도 | 검색 및 추천 목록의 순위 품질 평가 |
| **텍스트 생성 (NLP/LLM)** | **BLEU** | n-gram 정밀도 + Brevity Penalty | 기계 번역 등 참조 문장과의 토큰 일치도 (정밀도 중심) |
| | **ROUGE** (N, L) | n-gram 재현율 및 최장 공통 부분 수열(LCS) | 요약 품질 평가 (재현율 중심) |
| | **G-Eval (LLM-as-a-Judge)** | 다차원 루브릭 프롬프트를 통한 LLM 채점 | 유창성, 일관성, 논리성 등 고차원 생성 품질 평가 |
| **RAG 특화 지표 (TruLens / RAGAS)** | **Context Relevance** | $Query \leftrightarrow Context$ 관련성 | 검색된 문서가 질문과 직접적으로 관련되어 있는 정도 |
| | **Groundedness (Faithfulness)** | $Context \leftrightarrow Response$ 사실 일치도 | 답변이 검색된 컨텍스트에 기반하여 사실에 부합하는 정도 (환각 방지) |
| | **Answer Relevance** | $Query \leftrightarrow Response$ 응답 적합도 | 답변이 사용자의 원래 질문 의도를 충족하는 정도 |
| **이미지 생성** | **FID (Fréchet Inception Dist.)** | 실제 vs 생성 이미지 feature 분포 간 Fréchet 거리 | 낮을수록 실제 이미지 분포와 유사하고 자연스러움 |
| | **CLIP Score** | 텍스트 프롬프트와 생성 이미지 간 코사인 유사도 | 프롬프트 지시 사항의 이미지 반영도 평가 |

#### 3. 검증 및 오라클 전략
- **조합 테스팅 (Pairwise Testing)**: 파라미터 조합 중 결함 유발 가능성이 높은 2-way 조합을 체계적으로 추출.
- **테스트 오라클 해결 방안**: 
  - **벤치마킹(Benchmarking)**: ImageNet, GLUE, MMLU 등 공인 데이터셋 활용.
  - **변형 테스팅(Metamorphic Testing)**: 입력 변형에 따른 출력 간 불변 관계(MR) 검증.
  - **Back-to-back Testing**: 기존 Reference 모델과 신규 모델의 출력 차이 비교.
  - **전문가 패널(Expert Panel)** 및 **A/B Testing**.

### [QA 2] 강건성 (Robustness)

#### 1. 개념 및 4대 위협 유형
- **정의**: 비정상적 입력, 노이즈, 물리적 간섭, 도메인 시프트, 인프라 불안정 등 **4대 위협 상황**에서도 기능 정확성(Functional Correctness)을 유지하는 능력.
- **4대 위협 유형**:
  1. **입력 데이터 강건성**: Unseen/OOD(미학습 데이터), Biased(맥락 편향), Adversarial(적대적 공격), Invalid(형식적/논리적 결함).
  2. **외부 간섭 강건성**: 센서 노이즈, 통신 장애, 전자기 교란(EMI) 등 수집 채널 왜곡.
  3. **외부 환경 강건성**: Data Drift(분포 변화), 악천후/조도 변화(복원력 저해), 센서 노후화(신뢰성 저해).
  4. **추론 컴퓨팅 환경 강건성**: 가드레일 로직 결함, 서빙 엔진/OS/인프라의 비결정성 및 리소스 변동.

#### 2. 강건성 평가 지표 (Metrics)
| 지표 분류 | 지표 명칭 | 산출식 / 정의 | 의미 및 해석 |
| :--- | :--- | :--- | :--- |
| **정확성 기반** | **강건성 지수 (RS)** | $RS = \frac{\text{가혹 환경 정확도}}{\text{정상 환경 정확도}} \times 100 (\%)$ | 정상 대비 가혹 환경에서 보존된 정확도 비율 (100%에 가까울수록 우수) |
| | **상대적 저하율 (RCD)** | $RCD = \frac{\text{정상 정확도} - \text{가혹 정확도}}{\text{정상 정확도}} \times 100 (\%)$ | 가혹 환경으로 인해 손실된 성능 비율 (낮을수록 우수) |
| | **조건별 강건성 지수 ($RS_{c}$)** | 특정 조건(비, 안개, 소음, 조도 등)별 $RS$ | 환경별 취약점 파악 및 조건별 보존율 측정 |
| | **평균 오염 오류율 (mCE)** | $\text{mCE} = \frac{1}{N}\sum \frac{E_{\text{model}, c}}{E_{\text{baseline}, c}}$ | ImageNet-C 등 표준 15종 오염 데이터셋 대비 오류율 |
| **적대적 공격 기반** | **강건 정확도 (RA)** | 공격 데이터셋 평가 시의 정확도 | 최악의 적대적 공격 하에서 모델이 방어해 낸 정확도 |
| | **공격 성공률 (ASR)** | $ASR = \frac{\text{공격으로 오답이 된 샘플 수}}{\text{정상 상황 정답 수}} = 1 - RA$ | 공격자 입장에서의 침투 성공 비율 (낮을수록 안전) |
| | **공격 탐지/차단율** | $\frac{\text{차단된 공격 입력 수}}{\text{전체 유입된 공격 입력 수}} \times 100 (\%)$ | 적대적 입력(Jailbreak, Perturbation)의 사전 방어율 |
| | **정상 입력 오거부율 (FRR)** | $\frac{\text{차단된 정상 입력 수}}{\text{전체 정상 입력 수}} \times 100 (\%)$ | 가드레일이 정상 입력을 과도하게 차단하지 않는 정도 |
| **안정성 기반** | **추론 안정성 지수 (Stability)** | 연속 예측값의 표준편차 / 변동폭 | 입력에 미세 노이즈가 주입될 때 출력의 흔들림 정도 |
| | **예측 변동률 (Flicker Rate)** | 인접 프레임 간 불필요한 라벨 전환 비율 | 비디오 객체 인식 등에서 시간적 판단 일관성 측정 |

### [QA 3] 프라이버시 (Privacy)

#### 1. 개념 및 프레임워크
- **정의**: 개인 데이터의 부당하거나 불법적인 수집·사용으로 인한 사생활 침해로부터의 자유 (ISO/IEC 29100).
- **보호 대상**: 직접 식별자 및 간접 식별자를 포함하는 **PII(개인식별정보)** 및 **민감 정보(Sensitive Information)**.
- **위협 공격 기법**:
  - **멤버십 추론 공격 (MIA)**: 특정 데이터가 모델 훈련에 사용되었는지 여부를 역추론.
  - **속성 추론 공격 (AIA)**: 모델 출력을 통해 비공개된 개인의 민감 속성을 유추.
  - **학습 데이터 추출 공격**: 프롬프트 조작을 통해 학습 데이터 내 PII를 원문 그대로 추출.
  - **모델 역전 공격 (Model Inversion)**: 모델 출력/가중치로부터 원본 입력(얼굴, 지문 등)을 재복원.

#### 2. 프라이버시 평가 지표 (Metrics)
| 지표 분류 | 지표 명칭 | 수식 / 기준치 | 상세 설명 및 목표 |
| :--- | :--- | :--- | :--- |
| **내재적 보장 지표** | **차등 프라이버시 (DP $\varepsilon, \delta$)** | $P[M(D) \in S] \le e^\varepsilon P[M(D') \in S] + \delta$ | $\varepsilon$(프라이버시 손실 예산)이 작을수록 강력한 보호 (통상 $\varepsilon \le 1.0 \sim 3.0$) |
| | **K-익명성 (K-Anonymity)** | 동일 준식별자 레코드 수 $\ge k$ | 특정인을 최소 $k-1$명의 다른 사람과 구분할 수 없게 함 |
| | **L-다양성 (L-Diversity)** | 동질 그룹 내 민감 속성 종류 $\ge l$ | K-익명성의 동질성 공격(속성 추론)을 방어 |
| | **T-근접성 (T-Closeness)** | 그룹 내 속성 분포와 전체 분포 거리 $\le t$ | L-다양성의 왜곡된 분포(쏠림) 취약점 방어 |
| **적대적 공격 방어 지표** | **MIA 방어율 / MIA 정확도** | $\text{MIA-Accuracy} \approx 0.50$ (Random Guess) | 공격자가 훈련 데이터 포함 여부를 판별하지 못하는 정도 |
| | **학습 데이터 추출율** | $\frac{\text{유출된 PII 샘플 수}}{\text{전체 공격 시도 수}} \times 100 (\%)$ | 접두어/반복 공격 시 훈련 데이터 PII 암기·노출 비율 (0% 목표) |
| | **모델 역전 복원 유사도** | $\text{SSIM} \le \text{Threshold}$ / Cosine Sim 저하 | 역복원된 이미지와 실제 원본 간 구조적 유사도 억제 |
| **LLM 프라이버시 지표** | **PII 직접 노출률** | 응답 내 주민번호, 전화번호, 이메일 노출 비율 | 마스킹/필터링 가드레일의 PII 차단 완결성 |
| | **탈옥 시 PII 방어 성공률** | 프롬프트 인젝션 공격 시 PII 미노출 비율 | 시스템 프롬프트 및 RAG 문서 내 민감정보 은닉률 |

### [QA 4] 공정성 (Fairness)

#### 1. 개념 및 두 가지 공정성 패러다임
- **정의**: 기확립된 규범을 존중하며, 보호 속성(성별, 인종, 연령, 지역 등)에 따른 부당한 차별 없이 결과를 도출하는 능력.
- **보호 속성(Protected Attribute)** vs **대리 속성(Proxy Attribute)**: 성별/인종을 직접 배제하더라도 쇼핑 목록, 거주지 등 대리 속성을 통해 간접 차별이 발생할 수 있음.
- **개인 공정성 vs 그룹 공정성**:
  - **그룹 공정성**: 보호 그룹(A=0 vs A=1) 간 통계적 지표의 균등성.
  - **개인 공정성**: 유사한 자격을 갖춘 두 개인은 유사한 대우를 받아야 함.

#### 2. 공정성 평가 지표 (Metrics)
| 범주 | 지표 명칭 | 수식 / 기준치 | 상세 설명 |
| :--- | :--- | :--- | :--- |
| **그룹 공정성 (결과 배분)** | **Demographic Parity (DP)** | $\|P(\hat{Y}=1\|A=0) - P(\hat{Y}=1\|A=1)\| \le \epsilon$ | 보호 속성과 무관하게 긍정 판정률(선정률)이 동일해야 함 |
| | **Disparate Impact (DI)** | $\frac{P(\hat{Y}=1\|A=0)}{P(\hat{Y}=1\|A=1)} \ge 0.80$ | 4/5 룰(80% 규칙): 소수 집단 선정률이 다수 집단의 80% 이상이어야 함 |
| **그룹 공정성 (오류 양상)** | **Equal Opportunity (EO)** | $\|TPR_{A=0} - TPR_{A=1}\| \le \epsilon$ | 실제 자격을 갖춘 정답자($Y=1$) 중 긍정 판정률(재현율)이 동일 |
| | **Equalized Odds** | $TPR_{A=0} = TPR_{A=1}$ 및 $FPR_{A=0} = FPR_{A=1}$ | 그룹 간 True Positive Rate와 False Positive Rate가 모두 균등 |
| | **Predictive Equality** | $\|FPR_{A=0} - FPR_{A=1}\| \le \epsilon$ | 그룹 간 무고하게 불이익을 받을 확률(오탐률)이 균등 |
| **그룹 공정성 (정확도)** | **Accuracy Parity** | $\|Accuracy_{A=0} - Accuracy_{A=1}\| \le \epsilon$ | 그룹 간 모델의 전체 분류 정확도 차이가 없어야 함 |
| **개인 공정성** | **Consistency Score** | $1 - \frac{1}{n\cdot k}\sum_{i}\sum_{j \in kNN(i)} \|\hat{y}_i - \hat{y}_j\|$ | 거리 공간 상에서 가장 유사한 $k$명의 이웃 간 예측값 일치도 |
| | **반사실적 공정성 (Counterfactual)** | $P(\hat{Y}_{A \leftarrow 0}=y\|X) = P(\hat{Y}_{A \leftarrow 1}=y\|X)$ | 다른 모든 조건이 같고 보호 속성만 바뀌었을 때 결과 불변 |
| | **Theil Index** | $\frac{1}{n}\sum \frac{y_i}{\mu}\ln(\frac{y_i}{\mu})$ | 개인 간 예측 오차나 혜택의 불평등도 측정 (0에 가까울수록 공정) |
| **LLM 공정성** | **BBQ / KoBBQ 편향 점수** | 모호한 질문에서 고정관념에 기반한 답변 선택률 | 사회적 소수자/약자에 대한 편향 응답 억제 평가 |
| | **Toxicity / Hate Score** | 생성된 텍스트의 독성 지수 ($0.0 \sim 1.0$) | RealToxicityPrompts 벤치마크 기반 혐오 표현 생성률 |

### [QA 5] 수행 효율성 (Performance Efficiency)

#### 1. 개념 및 3대 분류
- **정의**: 명시된 조건 하에서, 명시된 시간 및 처리량 기준을 만족하며 자원을 효율적으로 사용하는 능력 (ISO/IEC 25010/25059).
- **3대 하위 특성**:
  1. **시간 효율성 (Time Behavior)**: 응답 시간(Latency) 및 처리량(Throughput).
  2. **자원 활용성 (Resource Utilization)**: GPU, CPU, VRAM, 전력, 네트워크 대역폭.
  3. **용량 (Capacity)**: 최대 동시 요청 수, 최대 배치 크기, 최대 컨텍스트 윈도우.

#### 2. 수행 효율성 평가 지표 (Metrics)
| 지표 분류 | 지표 명칭 | 단위 / 산출 정의 | 상세 설명 및 목표 |
| :--- | :--- | :--- | :--- |
| **시간 효율성** | **Inference Latency** | ms (단위: p50, p95, p99) | 입력 전달부터 최종 추론 결과 반환까지의 경과 시간 |
| | **Throughput / FPS / QPS** | FPS (Frames/sec), QPS (Queries/sec) | 단위 시간(1초)당 처리 완료된 요청 또는 프레임 수 |
| **LLM 서빙 지표** | **TTFT (Time to First Token)** | ms | 사용자 요청 후 첫 번째 토큰이 출력될 때까지의 반응 시간 |
| | **TPOT (Time Per Output Token)** | ms/token (Inter-Token Latency) | 첫 토큰 이후 후속 토큰이 생성되는 간격 시간 |
| | **TPS (Tokens Per Second)** | tokens/sec | 시스템 전체 또는 단일 스트림의 초당 토큰 생성량 |
| **자원 활용성** | **GPU / CPU Utilization** | $\%$ | 연산 장치의 평균 및 피크 가동률 |
| | **VRAM / Memory Footprint** | MB / GB | 모델 가중치, KV Cache, 런타임이 점유하는 메모리 크기 |
| | **에너지 / 전력 소비량** | Watt / 추론당 Joules / kWh | 하드웨어 전력 효율성 및 탄소 배출량 지표 |
| **용량 (Capacity)** | **Max Concurrency** | 동시 사용자 수 / 동시 요청 수 | SLA(지연 시간 제한)를 위반하지 않고 수용 가능한 최대 부하 |
| | **Max Context Length** | Tokens (예: 32k, 128k) | OOM(Out of Memory) 없이 지원 가능한 입력 문맥 한계 |
| **Agent 특화 지표** | **LLM Calls per User Request** | 호출 횟수 / Request | 사용자 요청 1건당 평균 LLM 호출 수 (Round-trip) |
| | **LLM Calls per Task** | 호출 횟수 / Task | Task 1개당 평균 LLM 호출 수 |
| | **Token Cost per Request** | 비용 ($ 또는 Token 수) | 요청 1건당 input/output token 비용 |
| | **Expensive Model Invocation Ratio** | $\%$ (고가 호출 / 전체 호출) | 고가 모델(GPT-4o, Claude 3.5 등) 호출 비율 |
| | **Replan Rate** | $\%$ (재계획 발생 수 / 전체 Task) | 실행 중 재계획(Replan) 발생 비율 |
| | **Deterministic Execution Ratio** | $\%$ (비LLM Task / 전체 Task) | LLM 없이 규칙/스크립트로 실행된 task 비율 |
| | **Task Success Rate** | $\%$ (성공 Task / 전체 Task) | 에이전트의 최종 목표 달성률 |

#### 3. Agent $\rightarrow$ LLM 수행 효율성 최적화 방안
> **참조 강의자료**: `6-AI-Quality-Performance Efficiency.pdf` (Page 19)

에이전트가 LLM과 연동할 때 **Prompt 및 Response 규모를 줄이고 비용/지연을 최소화**하기 위한 핵심 설계 원칙:

1. **LLM 호출 최소화 (Minimize LLM Invocations)**
   - 불필요한 반복 호출 억제: 매 단계마다 LLM을 호출하는 Incremental Plan 대신, 한 번에 전체 계획을 세우는 **One-shot Plan** 우선 적용.
   - 결정론적 룰 엔진(Rule-based / Code)으로 해결 가능한 영역은 LLM 호출 없이 바이패스 (`Deterministic Execution Ratio` 극대화).
2. **LLM 호출 Prompt 규모 최소화 (Minimize Prompt Context Size)**
   - **Context 선별**: RAG 및 메모리에서 전체가 아닌 **필요한 핵심 Context만 선별 주입**.
   - **Tool 정의 최적화**: 에이전트에 전체 도구 명세를 주입하지 않고, **해당 태스크에 필수적인 Tool만 동적으로 바인딩**.
3. **LLM Response 규모 최소화 (Minimize Response Output Size)**
   - JSON Schema, Function Call 구조 등을 지정하여 **Response 형식 및 출력 규모를 구체화/압축**.
   - 장황한 추론 텍스트 생성을 제한하고 필요한 액션/파라미터만 출력하도록 제어.
4. **Agent 루프 구조 최적화**
   - $\text{Goal} \rightarrow \text{Plan} \rightarrow \text{Execute} \rightarrow \text{Reflect}$ 생애주기에서 FM Gateway 캐싱 및 Context Retrieval Tool을 통한 효율적 질의 파이프라인 구성.

### [QA 6] 기능 적응성 (Functional Adaptability)

#### 1. 개념 및 운영 도메인(OD) 요소
- **정의**: 운영 환경의 다양한 변화에 대응하여 시스템 스스로를 적응시키는 능력.
- **운영 도메인(Operational Domain) 요소**: 지리적 구역(도심 $\rightarrow$ 고속도로/비포장), 물리 환경(온도, 조도, 바닥 재질), 법/규제 정책(스쿨존 속도 제한, 배출 규제), 센서/하드웨어 사양, 사용자 성향.
- **적응 유형**:
  - **적응 원인**: 도메인 요소 **확장(Expansion)** vs 도메인 요소 **변경(Change/Renewal)**.
  - **적응 방식**: **확정적 적응(Deterministic)**(사전 정의된 규칙/모드 전환) vs **진화적 적응(Evolutionary)**(운영 중 재학습/온라인 적응/가중치 갱신).

#### 2. 기능 적응성 평가 지표 (Metrics)
| 평가 단계 | 지표 명칭 | 수식 / 정의 | 상세 설명 및 목표 |
| :--- | :--- | :--- | :--- |
| **적응 과정 (Process)** | **도메인 변화 감지 정확도** | $\frac{\text{올바르게 감지된 환경 변화 수}}{\text{실제 발생한 환경 변화 수}} \times 100 (\%)$ | 비포장도로 진입, 신규 규제 수신 등 트리거 감지 정확도 |
| | **적응 모드 전환 성공률** | $\frac{\text{목표 모드로 정상 전환된 횟수}}{\text{전체 적응 전환 시도 횟수}} \times 100 (\%)$ | 상황에 맞는 최적 모드/파이프라인 선택 완결성 |
| | **적응 소요 시간 (Adaptation Latency)** | ms 또는 sec ($T_{\text{완료}} - T_{\text{감지}}$) | 변화 감지 시점부터 새 모델/파라미터 적용 완료까지 걸린 시간 |
| | **적응 리소스 오버헤드** | 적응 중 소모된 추가 GPU/네트워크 비용 | 런타임 적응 동작이 기존 서비스에 미치는 부하 |
| **적응 후 (Post-adaptation)** | **적응 후 품질 달성도** | $Q_{\text{post}} \ge \text{Target Quality}$ | 변화된 새 환경에서 목표 정확도(예: 95%) 달성 여부 |
| | **품질 회복률 (QRR)** | $QRR = \frac{Q_{\text{적응후}} - Q_{\text{미적응}}}{Q_{\text{정상}} - Q_{\text{미적응}}} \times 100 (\%)$ | 미적응 시 저하되었던 품질을 적응을 통해 회복한 비율 |
| | **안정화 시간 (Time to Stabilization)** | sec / frames | 적응 직후 출력 품질의 흔들림이 잦아들고 정상 상태에 도달하는 시간 |
| | **안정성 유지 지수 (Stability Index)** | 적응 후 일정 기간 동안의 분산/변동폭 | 모드 전환 후 잦은 채터링(흔들림) 없이 안정 유지 정도 |

### [QA 7] 제어 가능성 (Controllability)

#### 1. 개념 및 제어 목적
- **정의**: 제어 주체(인간 또는 상위 관제 시스템)가 AI 동작에 **개입(Intervene)**하여 시스템의 신뢰성을 회복하고 위험을 통제하는 능력.
- **제어 기능 유형**:
  1. **비즈니스 연속성 지원**: AI의 한계를 보완하여 임무를 완수 (교정 기능 - Correction, 보완 기능 - Compensation).
  2. **안전 상태 전환 (Fail-Safe)**: 위험 발생 시 즉각 안전 모드로 전환 (비상 정지, 저속 안전 운행).
- **제어 수준**:
  - **AI Application 수준 제어**: 수동 조종 전환, 원격 관제 개입, 워크플로우 승인/거부.
  - **AI 시스템 수준 제어**: 모델 가드레일 파라미터 강제 변경, Fallback 룰 적용, 저전력 추론 모드 강제.

#### 2. 제어 가능성 평가 지표 (Metrics)
| 지표 분류 | 지표 명칭 | 수식 / 기준치 | 상세 설명 및 목표 |
| :--- | :--- | :--- | :--- |
| **제어 정확성 (Correctness)** | **제어 개입 성공률** | $\frac{\text{의도한 제어 목적 달성 횟수}}{\text{전체 개입 시도 횟수}} \times 100 (\%)$ | 수동 탈출, 경로 재지정 등 개입 목적 완수 비율 |
| | **안전 상태 전환 성공률** | $\frac{\text{안전 상태로 정상 진입한 횟수}}{\text{비상 정지/전환 명령 횟수}} \times 100 (\%)$ | 위험 감지 시 Fail-Safe 모드로 완벽 진입 (100% 목표) |
| | **제어 의도 일치율** | $1 - \text{Intent Mismatch Rate}$ | 사용자의 조작 명령과 시스템 물리적 거동 간의 일치도 |
| **제어 효율성 (Efficiency)** | **제어 반응 지연 시간 (Intervention Latency)** | ms ($T_{\text{반응}} - T_{\text{명령}}$) | 개입 신호 인가 후 시스템이 즉각 반응하기까지의 지연 |
| | **안전 상태 도달 시간 (Time to Safe State)** | ms 또는 sec | 비상 명령 수신 후 기구적/논리적으로 완전히 정지·안정화되는 시간 |
| | **인간 개입률 (Human Intervention Rate)** | 단위 시간 또는 거리당 개입 횟수 | 평상시 자율성 수준 및 시스템 완성도 평가 지표 |

### [QA 8] 설명 용이성 (Explainability)

#### 1. 개념 및 관련 용어 구분
- **정의**: AI 시스템이 도출한 '결과'에 대하여 **'이유(동작 메커니즘)'**와 **'타당성(사회적·규제적 근거)'**을 인간이 납득할 수 있는 방식으로 표현하는 능력.
- **관련 개념 비교**:
  - **투명성 (Transparency)**: 시스템 목적, 학습 데이터, 구조, 한계점 정보 공개 (Model Card, System Card).
  - **해석 가능성 (Interpretability)**: 화이트박스 모델처럼 내부 수식/가중치를 수학적으로 직관 이해 가능한 정도.
  - **설명 용이성 (Explainability)**: 블랙박스 모델의 사후 설명(Post-hoc)을 포함하여 인간의 인지 체계에 맞게 표현하는 능력.
- **설명 모드 (Modes of Explanation)**:
  - **Local Explanation**: 개별 추론 결과 1건에 대한 근거 (LIME, SHAP, Attention Rollout).
  - **Global Explanation**: 모델 전체의 평균적 판단 기준 및 피처 중요도 (Global Feature Importance).
  - **반사실적 설명 (Counterfactual)**: "소득이 500만원 더 높았다면 대출이 승인되었을 것입니다"와 같은 대안 제시.
  - **예시 기반 설명 (Example-based)**: 판단에 가장 큰 영향을 준 학습 데이터 샘플 제시 (Influence Function).

#### 2. 설명 용이성 평가 지표 (Metrics)
| 평가 관점 | 지표 명칭 | 측정 방식 / 수식 | 상세 설명 및 목표 |
| :--- | :--- | :--- | :--- |
| **기술적 신뢰성 (Faithfulness)** | **설명 충실도 (Fidelity / Faithfulness)** | 중요 피처 제거 시 모델 출력 변화 상관관계 | 설명이 모델의 실제 내부 판단 로직을 왜곡 없이 반영하는 정도 |
| | **삭제 / 삽입 점수 (Deletion / Insertion Score)** | 피처를 순차 제거/추가 시 예측 확률의 급감/급증 곡선 아래 면적 | 중요하다고 표시된 피처의 실질적 영향력 검증 |
| | **설명 안정성 (Explanation Robustness)** | 미세 노이즈 주입 시 설명 변화량 측정 | 입력에 의미 없는 잡음이 섞여도 설명이 급변하지 않는 일관성 |
| **사용자 경험 및 실용성** | **설명 복잡도 (Explanation Complexity)** | 설명에 포함된 피처 수, 규칙 수, 문장 길이 | 과도하게 복잡하지 않고 인간이 이해하기 적절한 간결성 |
| | **사용자 이해도 / 납득도** | 사용자 평가 점수 (5점 Likert 척도) | 설명 수신자가 판단 사유를 이해하고 다음 행동을 결정할 수 있는 정도 |
| | **설명 생성 지연 시간 (Explanation Latency)** | ms | 추론 외에 설명을 추가 산출하는 데 소요되는 오버헤드 |
| **LLM / RAG 특화** | **CoT 논리 정합성 (Reasoning Coherence)** | 단계별 추론 과정의 사실성 및 논리적 비약 여부 | 중간 생각 과정(Chain-of-Thought)의 타당성 평가 |
| | **인용 정확도 (Citation Precision / Recall)** | 답변 내 인용 출처와 실제 원문 간 일치도 | RAG 답변에서 근거로 제시한 문서의 정확성 |

## 3. 품질 속성 간 우선순위(Priority) 및 Trade-off 분석

> **참조**: `10-AI-Quality-Priority & Trade-off.pdf`

### 3.1 AI 응용 분야별 품질 속성 우선순위
| AI 응용 유형 | 대표 서비스 사례 | 최우선 필수 품질 속성 (QA) |
| :--- | :--- | :--- |
| **개인화 · 추천 AI** | 커머스 상품 랭킹, OTT 콘텐츠 큐레이션, 금융 상품 추천 | **공정성**, **프라이버시**, **기능 적응성** |
| **인지 · 지각 AI** | 자율주행 객체 탐지, 제조 비전 검사, 음성 제어, 지능형 CCTV | **강건성**, **수행 효율성**, **기능 적응성** |
| **생성형 · 대화형 AI** | 멀티모달 챗봇, RAG 기반 질의응답, 문서 요약/작성 | **프라이버시**, **공정성**, **설명 용이성**, **기능 정확성** |
| **예측 · 진단 분석 AI** | 공정 설비 고장 예지, 환자 질환 악화 예측, 배터리 수명 예측 | **기능 정확성**, **강건성**, **설명 용이성** |
| **의사결정 · 에이전트 AI** | 전력망 배분 최적화, 물류 경로 플래닝, 자율형 AI 에이전트 | **제어 가능성**, **수행 효율성**, **강건성** |

### 3.2 핵심 QA Trade-off 관계
1. **품질 강화 vs 수행 효율성 (Latency / Throughput)**
   - 안전장치, 가드레일, 앙상블, 사후 검증, XAI 로직 추가는 지연 시간 증가 및 GPU 자원 소모를 유발함.
2. **공정성 vs 기능 정확성 (Fairness-Accuracy Pareto Frontier)**
   - 전체 오차 손실 함수를 최소화하면 다수 집단에 과적합되어 편향이 발생하며, 소수 집단 보호를 위해 편향을 강제 완화하면 전체 정확도가 일부 희생될 수 있음.
3. **프라이버시 vs 기능 정확성**
   - 차등 프라이버시(DP) 노이즈 주입 및 PII 마스킹은 데이터 원본 정보를 훼손하여 모델 예측 정밀도를 저하시킬 수 있음.
4. **설명 용이성 vs 기능 정확성**
   - 딥러닝/LLM과 같이 모델 복잡도(파라미터 수)가 높을수록 표현력과 정확도는 증가하지만, 내부 해석성(Interpretability)은 반비례하여 감소함.

## 4. 데이터 품질(Data Quality)과의 연계 매핑

> **참조**: `11-AI-Quality-Data Quality.pdf`

| AI 시스템 QA | 직접적 영향을 미치는 핵심 데이터 품질(DQ) 속성 | DQ 확보 방안 |
| :--- | :--- | :--- |
| **기능 정확성** | **Accuracy (정확성)**, **Completeness (완전성)**, **Relevance (적합성)** | 고품질 라벨링, 결측치 정제, 태스크 부합 피처 선정 |
| **강건성** | **Diversity (다양성)**, **Currentness (최신성)**, **Syntactic/Semantic Consistency** | 엣지 케이스 및 악조건 데이터 수집, 스키마 유효성 검증 |
| **프라이버시** | **Compliance (준수성)**, **Traceability (추적성)**, **Identifiability 관리** | PII 비식별화, 데이터 가명화, 접근 감사 추적 |
| **공정성** | **Balance (균형성)**, **Representativeness (대표성)** | 보호 속성별 계층화 샘플링, 편향 데이터 리밸런싱 |
| **수행 효율성** | **Precision (정밀도)**, **Similarity (중복성 제거)** | 피처 차원 축소, 중복 데이터 제거, 토큰 최적화 |
| **기능 적응성** | **Currentness (최신성)**, **Timeliness (적시성)** | 런타임 데이터 파이프라인 구축, 최신 도메인 데이터 수급 |
| **설명 용이성** | **Understandability (이해성)**, **Credibility (신뢰성)** | 메타데이터 표준화, 피처 명명 규칙 준수 |
